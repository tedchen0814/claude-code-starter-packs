# 收工同步助手

當使用者說「收工」、「準備換電腦」、「該同步的同步」或明確要求結束工作並同步時使用。一般的「先這樣」「結束了」不算，不確定就先問。

目標是把已完成的實質工作留在**工作筆記**（一定要做），並在專案是 Git repo 時同步到 Git；不把收工解讀為建立 repo、變更可見性或部署網站的授權。

## 執行方式

1. 依對話確認專案資料夾（實際放檔案的位置）。**不要求在 GDrive 內，也不要求是 Git repo。** 盤點本次對話完成的工作；若是 Git repo，一併看 `git status --short`。若沒有實質進度，說明不需同步並停止。
2. **建立或更新工作筆記（必做）**：
   - 專案資料夾已有 `工作筆記.md` → 以已驗證的本次工作更新「上次做到哪」、「下一步」與最近更動紀錄，有新坑就補進踩坑筆記。
   - 沒有 → 直接在專案資料夾新建 `工作筆記.md`（不必先問），結構：專案目標、上次做到哪、交付檔案、最近更動紀錄（日期＋摘要）、踩坑筆記、下一步／待確認。內容只寫對話中真的發生過的事，不捏造日期、數值或路徑。
   - 只有專案資料夾無法從對話推斷時，才問使用者放在哪裡。
3. **不是 Git repo** → 到此為止。報告「非 Git 倉庫，未提交」，不要自行 `git init`、不建立遠端。
4. **是 Git repo**：檢查變更清單。不可加入 `.codex/`、`.claude/`、`.env`、金鑰、credentials 或其他疑似敏感資料；遇到不明的未追蹤檔案或敏感資料時先列出並請使用者決定。只將本次實質變更的明確檔案（含工作筆記）加入 Git，使用具體的繁體中文 commit 訊息提交（標題行「動詞＋對象」，正文 3～5 條 bullet 說明變動與原因；不要只寫「更新」「修改」）。提交前摘要檔案與訊息。
5. 若已有可用 `origin` 與目前分支，推送該 commit。推送失敗時保留本機 commit、回報錯誤與可採取的下一步；不得自行重新登入、建立遠端 repo、改成公開 repo 或部署。
6. 用表格報告三項各自的結果（不適用時註明原因）：

   | 項目 | 內容 | 狀態 |
   |---|---|---|
   | 工作筆記 | 新建／更新的 `工作筆記.md`（完整路徑） | ✅ |
   | Git commit | 提交的檔案與訊息 | ✅ ／ 非 Git 倉庫，未提交 |
   | 遠端 push | origin／分支 | ✅ ／ 不適用 |

另外：資料夾若在雲端硬碟（GDrive 等）內，檔案會自動同步，不必處理。

## 安全界線

- 「收工」授權在專案資料夾內建立／更新工作筆記，以及同步已確認的當前專案工作；不授權 `git init`、建立 repo、公開 repo、GitHub Pages、權限變更或其他新的外部服務。
- 不使用 `git add .` 或 `git add -A`；選擇明確檔案。
- 不因為「不是 Git repo」或「找不到工作筆記」就省略工作筆記。
- 不以自動 hook 執行收工。若使用者要自動化，先說明它會在無人確認時提交或推送，並取得明確同意。
