# 開工接續

- 先依對話確認專案位置，讀取該專案資料夾的工作筆記（`工作筆記.md`），僅摘要最近進度、下一步與相關問題。**不要求在 GDrive 內，也不要求是 Git repo。** 目前資料夾沒有筆記時，可往上找一兩層。
- 是 Git repo 時才檢查本機狀態；已有 origin 時可 fetch 後判斷遠端差異（30 分鐘內 fetch 過就跳過）；遠端有新 commit 只提醒，不主動 pull。不是 Git repo（筆記、研究、簡報、硬體設計等專案）照常恢復工作脈絡，報告寫「非 Git 倉庫」，不要求建立 repo。
- 「開工」本身只授權讀取與檢查：不改檔、不 pull/rebase/checkout/reset。若同一句或既有對話已授權具體工作，檢查後直接接續該工作。
- 只有開工而沒有指定工作時，用精簡格式報告後等待選擇：

  ```
  📂 專案：<資料夾名>
  📘 上次做到哪：<1～2 句>
  🔧 本地 Git：<乾淨／有 N 個未提交變動／非 Git 倉庫>
  🌐 遠端：<最新／落後 N commits，要 pull 嗎？／不適用>
  ➡️ 建議下一步：1. …（最多兩項）
  ```

  有未提交變動時列出並問「繼續還是放棄」。不要把工作筆記全文倒出來。
- 遠端或工具無法使用時回報可確認的狀態，不自行登入、建立遠端或變更設定。
- 找不到工作筆記時，回報「這個專案還沒有工作筆記」並詢問要不要開始；不要自行建立（建檔是收工的事）。
